# 8. AI DISCLOSURE PROGRESS

| AI-assisted task | Affected section / file | Prompt used | Validation evidence |
|---|---|---|---|
| Project structure and home page | Landing page, navigation, hero, service categories, how-it-works section (`index.html`, `css/style.css`) | "Create the SerbisyoMo project structure and build a responsive home page for a Boac, Marinduque local service finder with navigation, a hero section, service categories, how-it-works steps, and a footer. Leave the other pages as placeholders for now." | The group opened the page in the browser, checked that all sections and navigation links were present, and tested it at a 375px mobile width to confirm there was no horizontal overflow. |
| Demonstration provider dataset | Provider data (`js/data.js`) | "Add a demonstration dataset of fictional Boac service providers with name, category, description, barangays covered, years of experience, rate, contact number, email, and availability. Include at least two providers per category and label it as demo data only." | The group checked that every record had all required fields, that rates were numbers, that every category had at least two providers, and that contact numbers were placeholders and not real people's details. |
| Provider directory search, filtering, and sorting | Provider directory (`providers.html`, `js/main.js`) | "Add search and combined filters (category, barangay, price range) to the provider directory with a result count, a friendly empty state, a Clear Filters button, and category preselection from the home page links. Add sorting by rating, experience, rate, and name." | The group tested each filter alone and in combination, searched for terms with no match, used Clear Filters, opened `providers.html?category=...` links from the home page, and checked the layout on mobile. |
| Provider profile page | Provider profile (`profile.html`, `js/main.js`) | "Build a provider profile page that reads the provider ID from the URL and shows the full details, ratings, specialties, and feedback, with a Request this Service link and a 'Provider not found' state for missing or invalid IDs." | The group opened valid, invalid, and missing IDs, confirmed that the request link carried the correct provider ID, and verified that the displayed details matched the data file. |
| Service request form and request history | Request form and My Requests (`request.html`, `requests.html`, `js/main.js`) | "Create a service request form with required-field, contact-number, and preferred-date validation that saves to localStorage with a Pending status. Create a My Requests page that lists requests newest first with status badges, demo status changes, and confirmation-based cancellation of pending requests." | The group submitted blank, invalid, and valid forms, checked the saved localStorage entries, tested sorting, status changes, cancellation, and the empty state, and removed test data afterward. |
| Responsive layout, accessibility, and navigation | All pages (`css/style.css`, `js/common.js`, all `.html` files) | "Improve the shared responsive layout and accessibility of all pages: add an accessible hamburger menu, consistent control sizes, visible keyboard focus, and reduced-motion support without changing existing features." | The group tested each page at 320px, 375px, 768px, and 1024px for overflow, used the keyboard to open and close the menu and move through controls, and followed the internal links to confirm none led to a missing page. |
| Accounts, storage layer, and BPBuddy-style improvements | Login, sign up, storage, and auth (`login.html`, `signup.html`, `js/storage.js`, `js/auth.js`, `js/common.js`) | "Apply the frontend-only patterns used in BPBuddy to SerbisyoMo: a versioned localStorage layer, role-aware Resident and Provider accounts with browser-hashed passwords, seeded demo accounts, role-guarded pages, toast messages, and an online/offline status indicator." | The group created accounts for both roles, logged in with the seeded demo accounts, and confirmed that a visitor who is not signed in as a provider is redirected away from the provider dashboard. |
| Provider dashboard, favorites, and account profile | Provider workspace, saved providers, and account page (`provider-dashboard.html`, `favorites.html`, `account.html`, `js/provider-dashboard.js`, `js/account.js`) | "Add a provider dashboard where providers can quote a request, add notes, and update its status; a Favorites page for residents; and an editable account profile that autofills the service request form." | The group sent a request as the demo resident, quoted and updated it as the demo provider, then logged back in as the resident to confirm the status, quote, and note appeared. Favorites and profile autofill were also checked. |
| Offline support | Service worker and web app manifest (`sw.js`, `manifest.webmanifest`) | "Add a service worker that caches the application shell and a web app manifest so the site still opens when the connection is lost." | The group served the site through a local server, turned on offline mode in the browser DevTools, and confirmed that the pages still loaded. |
| Testing checklist | Evaluation and quality checking | "Create a page-by-page testing checklist covering navigation, search and filters, the profile page, request validation, My Requests, responsive widths, keyboard focus, and cross-page links." | The group followed the checklist step by step, recorded results that did not match the expected outcome, and fixed those issues before finalizing the project. |
| Documentation | `README.md` and this disclosure | "Write the README and AI disclosure for SerbisyoMo following the format used in BPBuddy." | The group compared the README with the actual files, features, demo accounts, and run instructions in the project and corrected anything that did not match. |
