# 8. AI DISCLOSURE PROGRESS

**AI tools used:** Grok and Claude (coding), Gemini (summarizing, literature background, and drafting support), ChatGPT (grammar and wording).

| AI-assisted task | AI tool | Affected section / file | Prompt used | Validation evidence |
|---|---|---|---|---|
| Project structure and home page | Grok / Claude | Landing page, navigation, hero, service categories, how-it-works section (`index.html`, `css/style.css`) | "Create the SerbisyoMo project structure and build a responsive home page for a Boac, Marinduque local service finder with navigation, a hero section, service categories, how-it-works steps, and a footer. Leave the other pages as placeholders for now." | The group opened the page in the browser, checked that all sections and navigation links were present, and tested it at a 375px mobile width to confirm there was no horizontal overflow. |
| Demonstration provider dataset | Grok / Claude | Provider data (`js/data.js`) | "Add a demonstration dataset of fictional Boac service providers with name, category, description, barangays covered, years of experience, rate, contact number, email, and availability. Include at least two providers per category and label it as demo data only." | The group checked that every record had all required fields, that rates were numbers, that every category had at least two providers (the final set has 60 providers across 10 categories), and that contact numbers were placeholders and not real people's details. |
| Provider directory search, filtering, and sorting | Grok / Claude | Provider directory (`providers.html`, `js/main.js`) | "Add search and combined filters (category, barangay, price range) to the provider directory with a result count, a friendly empty state, a Clear Filters button, and category preselection from the home page links. Add sorting by rating, experience, rate, and name." | The group tested each filter alone and in combination, searched for terms with no match, used Clear Filters, opened `providers.html?category=...` links from the home page, and checked the layout on mobile. |
| Provider profile page and feedback | Grok / Claude | Provider profile (`profile.html`, `js/main.js`, `js/auth.js`) | "Build a provider profile page that reads the provider ID from the URL and shows the full details, ratings, specialties, and feedback, with a Request this Service link, a feedback form for logged-in users, and a 'Provider not found' state for missing or invalid IDs." | The group opened valid, invalid, and missing IDs, confirmed that the request link carried the correct provider ID, verified that the displayed details matched the data file, and submitted feedback while logged in and logged out. |
| Service request form and request history | Grok / Claude | Request form and My Requests (`request.html`, `requests.html`, `js/main.js`) | "Create a service request form with required-field, contact-number, and preferred-date validation that saves to localStorage with a Pending status. Create a My Requests page that lists requests newest first with status badges, demo status changes, and confirmation-based cancellation of pending requests." | The group submitted blank, invalid, and valid forms, checked the saved localStorage entries, tested sorting, status changes, cancellation, and the empty state, and removed test data afterward. |
| Responsive layout, accessibility, and navigation | Grok / Claude | All pages (`css/style.css`, `js/main.js`, all `.html` files) | "Improve the shared responsive layout and accessibility of all pages: add an accessible hamburger menu, consistent control sizes, visible keyboard focus, and reduced-motion support without changing existing features." | The group tested each page at 320px, 375px, 768px, and 1024px for overflow, used the keyboard to open and close the menu and move through controls, and followed the internal links to confirm none led to a missing page. |
| Accounts (log in and sign up) | Grok / Claude | Login, sign up, and session handling (`login.html`, `signup.html`, `js/auth.js`, `js/main.js`) | "Add browser-only log in and sign up with a browser-hashed password, a signed-in name and Log out button in the navigation, and a redirect to the page the visitor came from." | The group created an account, logged out and back in, entered a wrong password to check the error message, and confirmed that feedback on provider profiles requires a signed-in account. |
| Dashboard, saved providers, and home page improvements (BPBuddy-style) | Claude | Resident dashboard (`dashboard.html`, `js/dashboard.js`), saved-provider storage (`js/auth.js`), Save buttons (`js/main.js`), home page stats, top-rated providers, FAQ, and call to action (`index.html`), dashboard styles (`css/style.css`) | "Can you add some features from BPBuddy to SerbisyoMo, such as a dashboard that has information, to make it more like a website?" | The AI tested the flow in an automated browser run: it created an account, saved providers, submitted a request, changed its status with the demo control, completed a hiring tip, and confirmed that the summary cards, status chart, next steps, saved list, and home page statistics updated correctly. The page was also rendered at desktop and 390px widths. The group reviewed the result and compared the new dashboard with the BPBuddy workspace it was based on. |
| Literature background and summarizing | Gemini | Introduction, background, and references (`Project_Manuscript_SerbisyoMo_docs.docx`) | "Synthesize literature background on service finder platforms in rural island provinces using standard IEEE citation format." | The group opened each cited source, confirmed that it exists and supports the statement it is cited for, and rewrote the summaries in its own words to fit the Boac, Marinduque context. |
| Methodology, requirements, and technology justification | Gemini | Methodology, Core Features, and Technology Selection sections of the manuscript | "Structure an agile iterative methodology text and CRediT author contribution matrix according to standard academic project manuscript guidelines." | The group compared each description with the files and features that exist in the website and corrected statements that did not match the implemented project. |
| Grammar and wording | ChatGPT | Abstract, Introduction, Results and Discussion, and Conclusion of the manuscript; `README.md` | "Please improve the grammar and wording of this section. Keep the meaning the same and write in simple academic English." | The group read the revised text against the original, kept the meaning unchanged, and rejected edits that changed facts, numbers, or file names. |
| Testing checklist | Gemini / Claude | Evaluation and quality checking | "Create a page-by-page testing checklist covering navigation, search and filters, the profile page, request validation, My Requests, responsive widths, keyboard focus, and cross-page links." | The group followed the checklist step by step, recorded results that did not match the expected outcome, and fixed those issues before finalizing the project. |
| Documentation | Claude / ChatGPT | `README.md` and this disclosure | "Write the README and AI disclosure for SerbisyoMo following the format used in BPBuddy." | The group compared the README with the actual files, features, and run instructions in the project and corrected anything that did not match. |
